# Class-Diagram Readability + Nominal Conformance — Design Spec

- **Status:** Approved (design); implementation not started
- **Date:** 2026-07-02
- **Linear:** [MM-30](https://linear.app/mark-mansour/issue/MM-30/class-diagram-readability-nominal-protocol-conformance)
  (related: [MM-29](https://linear.app/mark-mansour/issue/MM-29/autogenerate-mermaid-diagrams-for-docs-class-sequence))
- **Scope:** Improve the generated class diagram (`docs/diagrams/class-core.md`) and declare the
  first-party seam implementations as nominal `Protocol` subclasses.
- **Related:** [pyreverse](https://pylint.readthedocs.io/en/latest/pyreverse.html),
  `docs/specs/2026-07-02-diagrams-design.md`, `docs/conventions/python.md`

## 1. Context & goal

MM-29 shipped an autogenerated Mermaid class diagram via pyreverse. Two problems make it hard to
read: pyreverse lists classes alphabetically with relationship edges at the bottom, and the seam
implementations satisfy their `Protocol`s **structurally** (no base class), so pyreverse draws no
implements-edges between (e.g.) `LLMProvider` and `AnthropicProvider`.

This change (1) declares nominal Protocol conformance on the first-party implementations — a real
correctness win (`ty` checks conformance) that also makes pyreverse draw the edges — and (2)
post-processes the pyreverse output so relationships come first and classes are grouped by module.

## 2. Goals / non-goals

**Goals**
- First-party implementations subclass their `Protocol` seams (nominal conformance).
- Generated class diagram: relationship edges first, then classes grouped by source module in a
  fixed flow order.
- The reshaping logic is a pure, unit-tested function.

**Non-goals (deferred)**
- Changing the ER or sequence diagrams (untouched).
- Adding synthetic realization edges in the generator (option B from the discussion) — nominal
  conformance (option A) makes pyreverse emit real edges, so no synthetic edges are needed.
- Any grouping scheme beyond by-module (hand-curated grouping rejected — drifts, needs upkeep).

## 3. Decisions (with rationale)

| Decision | Choice | Why |
|---|---|---|
| Conformance | **Nominal (option A)** — impls subclass their Protocol | `ty` conformance check at definition time + pyreverse draws the edges. Cost: a nominal import of the protocol module. |
| Grouping | **By source module** (`cls.__module__`) | Automatable, stays current as classes are added; matches "related classes". |
| Group order | **agent → llm → session → transport → events → messages** | Reads top-down from the orchestrator to the data it moves. |
| Edge placement | **Relationships first**, before class blocks | Readability of the generated source; Mermaid renders regardless of order. |
| Reshaping | **Post-process pyreverse text** | pyreverse offers no ordering/grouping options for mmd output. |

## 4. Part 1 — Nominal Protocol conformance

Add explicit Protocol bases (`saddlery/`):

| Class | File | New base |
|---|---|---|
| `FakeProvider` | `llm/fake.py` | `LLMProvider` |
| `AnthropicProvider` | `llm/anthropic_provider.py` | `LLMProvider` |
| `InMemorySessionStore` | `session.py` | `SessionStore` |
| `CliSink` | `transport/cli.py` | `EventSink` |
| `RecordingSink` | `transport/recording.py` | `EventSink` |

Each import of the Protocol is a runtime import (used as a base class), not a `TYPE_CHECKING`
import. `ty` verifies each class satisfies its Protocol. No behavior change — the existing tests
already instantiate these classes and exercise their methods, so they confirm nothing broke.

## 5. Part 2 — Generator post-processing (`core/scripts/gen_diagrams.py`)

- `_group_key(module: str) -> str` — returns the path component after `saddlery.`
  (`"saddlery.llm.base"` → `"llm"`, `"saddlery.events"` → `"events"`). Anything not under
  `saddlery.` returns `""` (fallback group).
- `GROUP_ORDER: list[str] = ["agent", "llm", "session", "transport", "events", "messages"]`.
- `reorder_class_diagram(mmd: str, class_module: dict[str, str]) -> str` — **pure**:
  1. Split the raw pyreverse mmd into the `classDiagram` header line, per-class blocks
     (`  class NAME {` … `  }`), and relationship lines (all other non-blank lines).
  2. Sort class blocks by `(group_rank, name)` where `group_rank` is the index of
     `_group_key(class_module.get(name, ""))` in `GROUP_ORDER`, or `len(GROUP_ORDER)` for unknown
     modules (fallback last).
  3. Re-emit: `classDiagram`, then the relationship lines (original order), then the sorted class
     blocks.
- `_saddlery_class_modules() -> dict[str, str]` — introspect the `saddlery` package (walk submodules
  with `pkgutil`, import each, record `cls.__name__ → cls.__module__` for classes defined in that
  module). Used by `main()` to build the `class_module` argument.
- `main()` — passes the raw pyreverse mmd through `reorder_class_diagram(mmd, _saddlery_class_modules())`
  before `render_class_md`.

## 6. Part 3 — Regenerate & verify

Run `make diagrams`; confirm `docs/diagrams/class-core.md` shows: relationship edges immediately
after `classDiagram` (including the new `--|>` Protocol edges), then classes grouped in the flow
order. Commit the regenerated diagram.

## 7. Testing

- `test_reorder_puts_relationships_first` — a small mmd (2 classes + 1 edge) → the edge line
  precedes both class blocks.
- `test_reorder_groups_by_module_flow_order` — classes from `agent`/`events`/`llm` modules with a
  supplied `class_module` map → class blocks appear in `GROUP_ORDER`.
- `test_reorder_unknown_module_goes_last` — a class absent from `class_module` sorts after known ones.
- `test_group_key_extracts_component_after_saddlery` — `_group_key` mapping.
- Part 1: existing suite + `ty check` (conformance).

## 8. Success criteria

- `uv run ty check` passes with the new Protocol bases (conformance holds).
- `uv run ruff check .` and `uv run pytest -q` pass.
- `make diagrams` produces a `class-core.md` with edges-first, module-grouped classes, and the new
  Protocol inheritance edges.
- No change to `saddlery` runtime behavior; ER and sequence diagrams unchanged.
