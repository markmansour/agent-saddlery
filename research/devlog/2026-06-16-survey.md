# 2026-06-16 — Survey & first decisions

## What we set out to do
Survey existing agent-harness designs, evaluate them, and produce a feature catalog + reference
library before writing any code. Goal: a general-purpose harness (not coding-specific) that I'll
run and extend, with multiple frontends (TUI, Web, desktop, IDE), MCP, and pluggable LLMs.

## Decisions & rationale
- **Reference designs:** OpenHands (closest match — event-sourced core, `step()` agent, typed tools
  + MCP), CrewAI (Crews + Flows workflow layer; AMP governance checklist), Goose (extensions *are*
  MCP servers), Claude Code (permission model + hooks).
- **Language: Python core + TypeScript frontends.** Mirrors OpenHands. Python has the richest agent
  ecosystem (LiteLLM, the reference frameworks) and is where the engine logic lives; TS owns the
  frontends (React Web, Ink TUI, Tauri desktop, VS Code). The split makes the protocol boundary a
  day-one constraint instead of an afterthought — which is exactly what multi-frontend needs.
  Considered pure TS (one language, weaker agent ecosystem) and pure Python (weak GUI/IDE story).
- **Wire protocol: AG-UI.** Open, event-based (~17 typed events over WS/SSE). Adopting it means every
  frontend speaks the same format and later surfaces are additive. Chose it over a custom schema to
  avoid reinventing a streaming protocol and to stay compatible with CopilotKit and the ecosystem.
- **First use cases:** resume writing, vacation research, and running small programs. This sets
  Phase 0 tools = file read/write + web search + web fetch + shell.
- **Sandbox: deferred** — but shell means real code execution from day one, so the **permission gate**
  (ask/allowlist via hooks) and **prompt-injection defense** move earlier (Phase 1) instead of waiting
  for the full Docker/microVM sandbox (now Phase 4).

## Dead-ends / tensions
- Wanted to defer all security with the sandbox, but adding shell to Phase 0 reopened code-execution
  risk. Resolved by pulling the permission gate forward rather than pulling the sandbox forward — keeps
  Phase 0 small while still guarding the obvious foot-gun (web/file content inducing a shell command).

## What we learned
- The five-layer architecture (core / provider / tools / execution / frontend, with security and
  observability cross-cutting) is remarkably consistent across every harness surveyed. The differences
  are emphasis and maturity, not shape.
- The new OpenHands Software Agent SDK (arXiv 2511.03690) is the single best blueprint: event-sourced
  state with deterministic replay, immutable config, typed tools + MCP, local↔remote portability.
- Prompt injection is the security story that doesn't need code execution to bite — untrusted web/file
  content is the attack surface regardless of the sandbox.
