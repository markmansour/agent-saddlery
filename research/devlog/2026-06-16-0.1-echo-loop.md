# 2026-06-16 — Building 0.1 (echo loop)

## What we set out to do
Implement slice 0.1 (MAR-5): a streaming chat echo loop on the Phase 0 core seams — events, session +
fold, `LLMProvider` seam (Anthropic), `EventSink`, and the `Agent.run` loop — via subagent-driven
development (fresh implementer per task + review).

## Decisions & rationale
- **Built with TDD, one vertical slice per module** (events → session → provider seam → sinks → agent
  loop → AnthropicProvider → CLI), each red-green-commit, each reviewed for spec + quality.
- **Stack:** Python 3.12 + `uv`, Pydantic v2 events, native `anthropic` async streaming
  (`messages.stream(...).text_stream`), pytest + `asyncio_mode=auto`, ruff.

## Dead-ends / things the reviews & build caught
- **Events weren't immutable.** Quality review flagged that "append-only source of truth" events were
  mutable; added `ConfigDict(frozen=True)` to `BaseEvent`. Cheap fix, real invariant.
- **A plan wart:** an unused `import pytest` in the session test — removed.
- **The CLI wiring test would have failed in CI.** `build_agent()` constructs `anthropic.AsyncAnthropic()`,
  which raises without an API key. Fixed by setting a dummy key via `monkeypatch` in the test (client
  construction makes no network call). Good reminder: anything that touches a provider client needs a
  key-free construction path or a stubbed env in tests.

## What we learned
- The seams paid off immediately: the whole agent loop is tested with a `FakeProvider` + `RecordingSink`,
  no network. The error invariant (`RunFinished` always emitted via `finally`) is verifiable in a unit test.
- Subagent-driven dev with verbatim-from-plan code mostly produced clean passes; the value showed up in
  the review catches (immutability, the api-key test gap) rather than the implementation itself.
